Summary: Reduce RenameModel operations that undo each other when optimizing migrations
Type: Cleanup/optimization
Component: Migrations
Version: dev
Severity: Normal
Keywords: optimizer squashmigrations
Has patch: yes

--- Description ---

Renaming a model and then renaming it back:

{{{#!python
[
    migrations.RenameModel("Foo", "Bar"),
    migrations.RenameModel("Bar", "Foo"),
]
}}}

is currently reduced to a rename of the model to its own name:

{{{#!python
[
    migrations.RenameModel("Foo", "Foo"),
]
}}}

The pair can be reduced to nothing. The same applies to longer chains, such as `Foo` → `Baa` → `Bar` → `Foo`.

The reduction only applies when the final name exactly matches the original. A case-only change, such as `Foo` → `Bar` → `foo`, still changes the model name in the state, so it is reduced to `RenameModel("Foo", "foo")` as before.

Reusing the original name while the model is renamed is handled, for example:

{{{#!python
[
    migrations.RenameModel("Foo", "Bar"),
    migrations.CreateModel("Foo", fields=[]),
    migrations.RenameModel("Foo", "Baz"),
    migrations.RenameModel("Bar", "Foo"),
]
}}}

is reduced to `[migrations.CreateModel("Baz", fields=[])]`.

Patch: https://github.com/adamchainz/django/commit/565f4f3d428e0758fe7f57a83c67d756fc5a054f
